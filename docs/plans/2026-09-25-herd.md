# herd Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `herd` CLI plus two skills that let one orchestrator Claude chat spawn, track, close and restore labelled worker chats in Herdr tabs.

**Architecture:** Python package, stdlib only. `registry.py` owns the JSON state, `herdr.py` wraps the `herdr` binary, `cli.py` implements the commands on top of both. Skills in `skills/` are symlinked into `~/.claude/skills/`.

**Tech Stack:** Python 3.11+, uv (`uv tool install --editable`), pytest, herdr 0.9.1, Claude Code CLI.

**Spec:** `docs/specs/2026-09-25-herd-design.md`

## Global Constraints

- State dir `~/.local/state/herd/` (override `HERD_STATE_DIR`), one `<orch-slug>.json` per orchestrator, atomic writes.
- Model ids: `opus` → `claude-opus-5-5`, `fable` → `claude-fable-5-1`.
- Tab label `<model> · <label>`; review marker prefix `👀 `; workspace label `◆ <label>`.
- Herdr agent name: label lowercased, non `[a-z0-9]` runs to `-`, must start with a letter, max 32 chars, deduplicated with `-2`, `-3`.
- Workers start with `--dangerously-skip-permissions` (Eddy runs every session in bypass).
- Fail loud: every failed herdr call exits non zero with herdr's message; the worker is marked `failed`.
- No dashes as punctuation in any user facing text.

## Review Focus

1. Spawning while Herdr is not reachable (`HERDR_ENV` unset or socket gone): expect a clear error before the registry changes.
2. Two workers with labels that slug the same (`Drip copy` and `drip-copy`): expect distinct herdr names, both restorable.
3. Restore when some workers are already open: expect no duplicate tabs, checked by session id.
4. `herd close` on a worker still `working`: expect refusal, tab left alone.
5. Registry file half written by a crash: expect atomic rename so the old file survives.
